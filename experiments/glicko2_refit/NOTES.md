# Glicko-2の収束改善の探索（未提出の実験記録）

2026-11-27に実施した探索の記録です。結果を見てから提出するか決めるため、PRは作成していません。`refit_probe.cpp` は試作で、テストはまだありません。

## 結論

- 全履歴の再推定（評価時点ごとに、それまでの全試合からGlicko-2尺度のレートを推定し直す）で、評価用10試行のMSEの平均が今のGlicko-2より12.0%下がった。10試行すべてで改善した（−10.4〜−14.0%）。
- 生成モデルを知っている推定器（上限の目安）でも12.6%で、15%の削減はこのデータでは達成できない。再推定は、今の値と上限の差の95%を埋めた。
- 更新期間を1試合にしても−8.5%で、再推定に及ばない。期間はチームで決める条件なので参考扱い。

## 方法

| 方法 | 内容 |
| --- | --- |
| 今のGlicko-2 | 初期RD 350・σ 0.06・τ 0.5、期間10試合（既存の `glicko2.cpp` と同じ） |
| 調整済み | 初期RD 250・σ 0.005・τ 0.5（`docs/glicko2-tuning.md` の結果） |
| 全履歴の再推定 | 尤度はGlicko-2のE（ロジスティック）、事前分布は全員N(1500, 210²)。Gauss-Seidel法のニュートン更新で事後最頻値を求め（最大ステップが1e-10未満で停止）、RDは対角のラプラス近似。予測はGlicko-2と同じ式 |
| 上限の目安 | 生成モデルのプロビット尤度と能力の事前分布N(0,1)を使う推定器。生成モデルを知っているため提案手法ではない。予測はガウス事後分布での期待値 |

調整用の5試行（シード2026112511〜53）で初期RDなどを選び、評価用の10試行（2026113011〜2026113103）で確認した。シードの規則は `configs/glicko2_tuning/` と同じ。

## 注意

- 再推定は能力が変わらないことを前提にしている。能力が変化する条件では、変化のモデル（Whole-History Ratingのような時間方向の事前分布）が必要になる。
- 再推定は各評価時点で全履歴を使うため、計算量が履歴とともに増える。1,000人・200試合では1試行（20時点）で約2秒（Apple M4、1スレッド、5試行で9.7秒）。
- 初期RD 210は、能力の標準偏差をレート尺度へ換算した約209点に近い。生成モデルの能力分布に依存する値である。
- 他の手法は調整していない。比較に使う場合は同じ予算で調整するか、感度分析として示す。

## 再現

```sh
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build/release
c++ -std=c++17 -O3 -Iinclude experiments/glicko2_refit/refit_probe.cpp build/release/libproject10_core.a -o build/release/refit_probe
./build/release/refit_probe logistic 210 1 evaluation   # 再推定
./build/release/refit_probe oracle 0 0 evaluation       # 上限の目安
./build/release/project10_glicko2_tuning configs/glicko2_convergence/period_01_evaluation.json runs/glicko2_convergence/period_01_evaluation
```
