# 先手・後手を含む比較実験の基盤

先手・後手の条件付き予測と対戦前評価、およびranked Glicko-2の固定参照分布を使った比較実験の実装を説明します。2026-10-28の依頼に基づき、[Advantage-Elo v0仕様](https://app.notion.com/p/402751d0ef6d81038f5de1ad101ee495)とPR #28の参照方式に対応しました。条件や学習率の設定例は、チームで採用済みの最終研究条件ではありません。既存手法の更新式は変更していません。実行コマンドは[README](../README.md#先手有利ありなしの比較実験)を参照してください。

## 生成モデルと乱数

`comparison`のない設定は従来の生成・評価処理を使います。比較設定では次を明記します。

```json
"comparison": {"scenario": "S1", "side_advantage": 1, "condition_seed": 2026102808},
"advantage_elo": {"initial_advantage": 0, "k_advantage": 1}
```

`S0`は有利幅0、`S1`は有限の正の有利幅が必須です。各試合で勝敗を生成する前に、独立した`mt19937_64(condition_seed)`のベルヌーイ分布で`z=+1/-1`を半々に割り当てます。`+1`は履歴のAが先手、`-1`はBが先手です。割当数を強制的に同数に揃える方式ではありません。

真の勝率は`Phi((theta_a - theta_b + side_advantage * z) / (sqrt(2) * performance_std))`です。第7回会議のプロビットモデルに、先手・後手による有利・不利を加えます。有利幅は潜在能力と同じ単位で表し、推定器が学習するElo尺度の条件効果とは区別します。例えば同じ能力・`performance_std=1`・有利幅1なら、先手の真の勝率は約0.76025です。有利幅0では従来の関数で計算し、能力・対戦組み合わせ・勝敗の生成器は変更しません。

PR #28反映前に実行した設定と参照元は以下です。人数1,000・200対戦、期間と評価間隔10です。これらの成果物は変更しません。新しい固定参照方式で実験する場合は、新しいrun IDを使用してください。

| 条件 | 参照学習用 | 評価用 | 有利幅 |
| --- | --- | --- | --- |
| S1 | run 4 | run 5 | 1 |
| S0 | run 6 | run 7 | 0 |

run 4と6、run 5と7はそれぞれ同じ4シードを使います。条件の有無による比較を同じ能力・組合せ・条件割当で行えます。勝敗用乱数のシードも同じですが、真の勝率が違うため勝敗は変わります。同じ実験run内の各手法には同一の履歴を渡します。別シード組での繰り返しと集計は後続作業です。

## 入力と成果物

`matches.csv`の既存5列は維持します。追加する`conditions.csv`は`match_id,z`の2列で、全対戦を漏れ・重複なく含めます。先手・後手の情報を更新・予測に使うのはAdvantage-Eloだけです。既存4手法とranked Glicko-2には5列の履歴をそのまま渡し、先手・後手の情報を使わない手法として比較します。

一括CLIは推定器専用の作業ディレクトリに、プレイヤーID、履歴、推定に必要な設定だけをコピーします。能力分布、生成用シード、`performance_std`、真の有利幅は設定から除外します。Advantage-Eloには条件CSV、ranked Glicko-2には参照レートCSVを個別に追加します。潜在能力・正解勝率はコピーしません。評価用には、すべての設定を含むスナップショットをrun直下に保存します。

| 成果物 | 内容 |
| --- | --- |
| `ground_truth.csv` | 既存3列の形式。先手・後手の真の勝率の等確率混合 |
| `ground_truth_positive.csv` / `ground_truth_negative.csv` | それぞれz=+1/-1の条件付き正解。評価専用 |
| `advantage_elo.csv` | 比較モードでは`run_id,matches_per_player,player_a,player_b,z,predicted_p_a_wins`。全ペア・全評価時点で両側を出力 |
| 他手法の予測CSV | 従来の5列。条件を観測しない単一の予測確率 |
| `online_predictions.csv` | `run_id,match_id,z,result_a,p_elo,p_advantage`。両手法の予測を更新前に計算してから、同じ結果で各状態を更新 |
| `online_metrics.csv` | `run_id,matches_per_player,elo_log_loss,advantage_log_loss,elo_brier,advantage_brier` |

Eloの対戦前スコアは、Elo本体と同じ公開APIを使い、初期値1500・K=32・scale=400から履歴を順に処理して求めます。Elo本体の数式を重複実装していません。Advantage-Eloも同じ基礎パラメータに加え、設定された条件効果の初期値と学習率を使います。非有限値、不正な先手・後手の指定、未知のIDやIDの重複・欠落、履歴と異なる勝敗・条件・対戦順をエラーにします。

## 評価方法

Elo対Advantage-Eloの主な比較は、結果を観測する前の各試合の`p`に対するLog Lossです。`y=result_a`として`-[y log(p)+(1-y) log(1-p)]`を計算します。数値安定化のためLog Lossに限って`p`を`[1e-15,1-1e-15]`へ制限します。副指標のBrierスコアは`(p-y)^2`で、二値問題の片側確率の定義です。保存する確率とBrierにはクリップを適用しません。両指標は各チェックポイントまでの全対戦の累積平均です。現段階ではこの対戦前評価はEloとAdvantage-Eloの2手法のみです。

全手法の補助指標は、同じ評価時点、全`a<b`のペア、z=±1を対象とする**条件付きMSE**です。`sum_pairs sum_z (prediction(a,b,z)-truth(a,b,z))^2 / (2 * pair_count)`を計算します。先手・後手の情報を使わない手法は、同じ予測を両条件に適用します。既存のMSE検証・集計処理を各条件に適用し、得られた2つのMSEを等しい重みで平均します。予測を平均してから二乗する方式とは異なります。`--comparison`を付けずに`--all-methods`で実行したS0のグラフとは、Advantage-Eloの評価方法が異なる点に注意してください。

3種類の図の横軸は1人当たりの累積対戦数です。MSE・Log Loss・Brierの縦軸はいずれも下限を0とし、上限はデータに合わせて自動調整します。各曲線を識別できる凡例と、グラフ全体のグリッドを付けます。描画データと条件は`graphs/plot.gp`に保存します。

## PR #28の固定参照

6手法を一括実行するには`--all-methods`を指定します。条件付き評価も行う場合は`--comparison --all-methods`を指定してください。ranked Glicko-2の参照元は、PR #28で導入した`samples/glicko_baseline/`の固定分布です。先手有利なしの通常実行の例は[run_0008の設定](../configs/run_0008/config.json)、出典・ハッシュ・生成条件は[固定参照の説明](../samples/glicko_baseline/README.md)を参照してください。

新規実行前に設定とレートCSVを読み、ヘッダー、件数と設定人数との一致、値の有限性を検査します。参照用と評価用のrun IDが異なることと、能力・対戦組み合わせ・勝敗の各シードが、対応する参照用の値と異なることも確認します。分布の学習人数と評価人数は異なっていてもかまいません。参照分布はS0・1,000人・各200対戦で生成されており、S1の評価用データと生成条件を揃える必要はありません。

読み込んだ設定とレートは、評価runの`ranked_reference/glicko_baseline/`に保存します。推定器専用の作業ディレクトリには、ranked Glicko-2が参照する相対パスにCSVだけを配置し、参照分布の生成設定は渡しません。評価run自身のGlicko-2最終分布は使いません。ranked Glicko-2の式・定数はPR #28の実装を維持します。

**ranked Glicko-2は、評価用とは別のデータで学習した分布を利用します。** また、先手情報を利用するのはAdvantage-Eloだけです。このため、各手法の観測情報・学習予算は揃っていません。現在のS1実験は先手情報を利用する効果の検証として扱い、同じ情報条件による6手法の優劣の結論には使いません。共通条件での主比較を行うには、利用可能な情報・学習データ・予測対象をどう揃えるか、別途決める必要があります。

## 保護と再利用

比較設定のあるrunでは`--comparison`が必須です。通常の4手法、固定参照を使う通常S0の6手法、条件付き評価の5手法、固定参照と条件付き評価を使う6手法では、異なるモードの成果物を再利用できません。固定参照を使う2つのモードは、それぞれマーカーの`mode=six_method_fixed_reference_v1`と`conditional_fixed_reference_v1`で識別します。比較用runは、生成CLIの上書き確認に`y`と入力しても上書きできません。

旧オプション`--ranked-reference-run ID`は使用できません。旧方式のrun_0003やrun_0005・0007は、新しい参照方式で上書き・再利用できません。従来の条件付き5手法のモードは引き続き使用できます。旧方式で保存した独立した参照データは、当時の結果を描画する際の検査に使用できます。

`--reuse-existing`では、入力・予測・MSEと条件CSVを検証します。潜在能力と条件付き正解勝率、対戦前ログと対戦履歴の整合性、スコアの再計算結果との一致も確認します。保存した固定参照については、形式・人数・シードを検査します。run内に保存した参照分布を再利用するため、元の`samples/`が移動・更新されても参照分布は変わりません。

欠落した評価CSVはログから再生成できます。Advantage-Eloの予測と対戦前ログ、標準Glicko-2の予測と最終レートはそれぞれ一組として扱い、片方だけ残った場合は停止します。標準Glicko-2最終レートはrankedの入力ではなく、標準手法自身の補助成果物です。

これらは形式・数値の整合性の検証であり、過去のコードで生成されたことの暗号学的な証明ではありません。コミットID・未コミット差分・環境・入力ハッシュ等は実験時に補ってください。高度な復旧、履歴管理、複数試行の自動実行・平均・信頼区間、他手法の対戦前評価は未実装です。

## 検証範囲

WSL2 UbuntuのC++17 Debugで、既存分を含むCTest全37件が成功しました。小規模なS0/S1のデータ生成から、5手法または固定参照を使う6手法の予測、条件付きMSEの計算、3種類のSVG／PNGの生成まで確認しています。追加したテストでは、正規分布の既知の値、条件の反転、S0での従来の対戦履歴との一致、手計算によるMSE・Log Loss・Brierとの照合を確認しました。更新前の予測ログ、実際の先手・後手に基づく更新、推定器への入力の分離、ロック、固定参照が変更されないこと、成果物の再利用と不足分の再生成も検証しています。不正な条件、参照元と同じrun IDやシード、壊れた成果物を使った実行が拒否されることも確認しました。

固定参照方式によるrun_0008の1,000人・各200対戦の実験と、追加機能のWindows／MSVCでの動作確認は未実施です。PR #28以前のrun_0004〜0007の実験結果とは参照方式が異なります。少人数・固定シードの動作確認だけでは、性能の優劣は判断できません。正式評価では、複数試行に使うシードの組、学習率、有利幅を事前に固定し、結果を見ながら設定を調整する段階と最終評価を分けてください。
