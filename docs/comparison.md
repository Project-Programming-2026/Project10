# 先手・後手を含む比較実験の基盤

2026-10-28の「比較できる土台にする」という依頼に対する実装と、PR #28の固定参照への接続を記録します。[Advantage-Elo v0仕様](https://app.notion.com/p/402751d0ef6d81038f5de1ad101ee495)の条件付き予測・対戦前評価を参照しました。条件や学習率の設定例を、チームで採用済みの最終研究条件として扱うものではありません。既存手法の更新式は変更していません。実行コマンドは[README](../README.md#先手有利ありなしの比較実験)を参照してください。

## 生成モデルと乱数

`comparison`のない設定は従来の生成・評価処理を使います。比較設定では次を明記します。

```json
"comparison": {"scenario": "S1", "side_advantage": 1, "condition_seed": 2026102808},
"advantage_elo": {"initial_advantage": 0, "k_advantage": 1}
```

`S0`は有利幅0、`S1`は有限の正の有利幅が必須です。各試合で勝敗を生成する前に、独立した`mt19937_64(condition_seed)`のベルヌーイ分布で`z=+1/-1`を半々に割り当てます。`+1`は履歴のAが先手、`-1`はBが先手です。割当数を強制的に同数に揃える方式ではありません。

真の勝率は`Phi((theta_a - theta_b + side_advantage * z) / (sqrt(2) * performance_std))`です。第7回会議のプロビットモデルに側による位置の差を加えます。有利幅は潜在能力の単位であり、推定器が学習するElo尺度の条件効果とは異なります。例えば同じ能力・`performance_std=1`・有利幅1なら、先手の真の勝率は約0.76025です。有利幅0の計算は従来関数へ委譲し、能力・組合せ・勝敗の生成器を変更しません。

PR #28反映前に実行した設定と参照元は以下です。人数1,000・200対戦、期間と評価間隔10です。これらの成果物は変更しません。新しい固定参照方式で実験する場合は、新しいrun IDを使用してください。

| 条件 | 参照学習用 | 評価用 | 有利幅 |
| --- | --- | --- | --- |
| S1 | run 4 | run 5 | 1 |
| S0 | run 6 | run 7 | 0 |

run 4と6、run 5と7はそれぞれ同じ4シードを使います。条件の有無による比較を同じ能力・組合せ・条件割当で行えます。勝敗用乱数のシードも同じですが、真の勝率が違うため勝敗は変わります。同じ実験run内の各手法には同一の履歴を渡します。別シード組での繰り返しと集計は後続作業です。

## 入力と成果物

`matches.csv`の既存5列は維持します。追加する`conditions.csv`は`match_id,z`の2列で、全対戦を漏れ・重複なく含めます。Advantage-Eloだけがこの側の情報を更新・予測に使います。既存4手法とranked Glicko-2には5列の履歴をそのまま渡し、側を観測しない比較対象とします。

一括CLIは推定器用の隔離作業先へ、プレイヤーID、履歴、必要な推定用設定だけをコピーします。能力分布、生成シード、`performance_std`、真の有利幅は設定から除外します。Advantage-Eloには条件CSV、ranked Glicko-2には参照レートCSVを個別に追加します。潜在能力・正解勝率はコピーしません。評価側の完全な設定スナップショットはrun直下に保存します。

| 成果物 | 内容 |
| --- | --- |
| `ground_truth.csv` | 既存3列の形式。先手・後手の真の勝率の等確率混合 |
| `ground_truth_positive.csv` / `ground_truth_negative.csv` | それぞれz=+1/-1の条件付き正解。評価専用 |
| `advantage_elo.csv` | 比較モードでは`run_id,matches_per_player,player_a,player_b,z,predicted_p_a_wins`。全ペア・全評価時点で両側を出力 |
| 他手法の予測CSV | 従来の5列。条件を観測しない単一の予測確率 |
| `online_predictions.csv` | `run_id,match_id,z,result_a,p_elo,p_advantage`。両手法の予測を更新前に計算してから、同じ結果で各状態を更新 |
| `online_metrics.csv` | `run_id,matches_per_player,elo_log_loss,advantage_log_loss,elo_brier,advantage_brier` |

Eloの対戦前スコア用状態は、Elo本体と同じ公開API・初期値1500・K=32・scale=400で履歴を再生します。Elo本体の数式を重複実装していません。Advantage-Eloも同じ基礎パラメータで、設定された初期条件効果と学習率を使います。非有限値、無効な側、未知・重複・欠落ID、履歴と異なる勝敗・条件・対戦順をエラーにします。

## 評価方法

Elo対Advantage-Eloの主な比較は、結果を観測する前の各試合の`p`に対するLog Lossです。`y=result_a`として`-[y log(p)+(1-y) log(1-p)]`を計算します。数値安定化のためLog Lossに限って`p`を`[1e-15,1-1e-15]`へ制限します。副指標のBrierスコアは`(p-y)^2`で、二値問題の片側確率の定義です。保存する確率とBrierにはクリップを適用しません。両指標は各チェックポイントまでの全対戦の累積平均です。現段階ではこの対戦前評価はEloとAdvantage-Eloの2手法のみです。

全手法の補助指標は、同じ時点・全`a<b`のペア・z=±1での**条件付きMSE**です。`sum_pairs sum_z (prediction(a,b,z)-truth(a,b,z))^2 / (2 * pair_count)`を計算します。側を使わない手法は同じ予測を両条件へ適用します。既存のMSE検証・集計器を両条件に使い、両結果を半々で平均します。予測を平均してから二乗する方式とは異なります。従来の`--all-methods`のS0図とAdvantage-Eloの評価値を混同しないでください。

3種類の図の横軸は1人当たりの累積対戦数です。MSEの縦軸は0始まりの既存の自動上限、Log Loss・Brierの縦軸も0始まりの自動上限を使います。全曲線に凡例とグリッドを付けます。描画データと条件は`graphs/plot.gp`に保存します。

## PR #28の固定参照

現在の6手法一括実行は`--all-methods`を指定します。条件付き評価を行う場合は`--comparison --all-methods`です。ranked Glicko-2の参照元は常にPR #28の`samples/glicko_baseline/`です。通常S0の実行例は[run_0008の設定](../configs/run_0008/config.json)、出典・ハッシュ・生成条件は[固定参照の説明](../samples/glicko_baseline/README.md)を参照してください。

新規実行前に設定とレートCSVを読み、ヘッダー・参照設定の人数・有限値、参照と評価のrun ID・対応する能力／組合せ／勝敗シードの相違を検査します。分布の学習人数は評価人数と独立です。参照はS0・1,000人・200対戦の分布であり、S1の評価条件と同じ生成条件を要求する方式ではありません。

取得した設定とレートは、評価runの`ranked_reference/glicko_baseline/`へ固定保存します。推定器の隔離作業先には、PR #28が読む相対パスのCSVだけを配置し、完全な参照生成設定は渡しません。評価run自身のGlicko-2最終分布は使いません。ranked側の式・定数もPR #28の実装を維持します。

**この接続は、独立した追加学習データを利用する手法の評価です。** Advantage-Eloだけが先手情報を利用することも含めて、観測情報・学習予算が他手法と異なります。現在のS1実験は先手情報を利用する効果の検証として扱い、同じ情報条件による6手法の優劣の結論には使いません。共通条件での主比較には、利用可能な情報・学習データ・予測対象の統一を別途決める必要があります。

## 保護と再利用

比較設定のあるrunでは`--comparison`が必須です。通常4手法、通常S0の固定参照6手法、条件付き5手法、条件付き固定参照6手法の各モードを混ぜて再利用しません。固定参照の新マーカーは、それぞれ`mode=six_method_fixed_reference_v1`と`conditional_fixed_reference_v1`です。比較用runは生成CLIの確認へ`y`を入力しても上書きしません。

旧`--ranked-reference-run ID`は拒否します。旧方式のrun_0003やrun_0005・0007を、新しい参照方式で上書き・再利用しません。従来の条件付き5手法のモードは維持します。保存済みの旧独立参照データは旧結果の描画時の検査に引き続き使用できます。

`--reuse-existing`は、入力・予測・MSE、条件CSV、潜在能力と条件付き正解、対戦前ログと履歴、スコアの再計算、保存した固定参照の形式・人数・シードを検査します。再利用する参照はrun内の固定保存版なので、外部のsamplesが移動・更新されてもそのrunの分布は切り替わりません。

欠落した評価CSVはログから再生成できます。Advantage-Eloの予測と対戦前ログ、標準Glicko-2の予測と最終レートはそれぞれ一組として扱い、片方だけ残った場合は停止します。標準Glicko-2最終レートはrankedの入力ではなく、標準手法自身の補助成果物です。

これらは形式・数値の整合性の検証であり、過去のコードで生成されたことの暗号学的な証明ではありません。コミットID・未コミット差分・環境・入力ハッシュ等は実験時に補ってください。高度な復旧、履歴管理、複数試行の自動実行・平均・信頼区間、他手法の対戦前評価は未実装です。
