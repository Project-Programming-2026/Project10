# Advantage-Elo の仕組みとオンライン Newton 更新

[実装](../src/ratings/advantage_elo.cpp)（ヘッダ: [advantage_elo.hpp](../include/project10/ratings/advantage_elo.hpp)）は、1対1・引き分けなしの対戦において、プレイヤーごとの基礎実力 `R_i` と全プレイヤー共通の先手有利 `a` を同時に学習する手法です。

## 勝率の予測式

2人の推定レート `R_A`, `R_B`、先手有利 `a`（Eloポイント単位）、先手条件 `z ∈ {+1, -1}`（`+1` は A が先手、`-1` は B が先手）から、A が勝つ確率を次で予測します。

```text
beta = ln(10) / scale
p_A  = 1 / (1 + 10^(-(R_A - R_B + a * z) / scale))
```

## 先手有利 `a` の2つの更新方法

個人レート `R_A`, `R_B` の更新は両方式で共通です（`R_A' = R_A + K * (y - p_A)`、`R_B' = R_B - K * (y - p_A)`、ただし `y ∈ {0, 1}` は A の勝敗）。先手有利 `a` の更新方法は `AdvantageUpdateMethod` で選べます。

### 1. `FixedStep`（従来の固定幅・v0既定）

```text
a' = a + kAdvantage * z * (y - p_A)
```

1試合あたりの更新幅 `kAdvantage` を固定して更新します（`kAdvantage = 0` なら通常 Elo と一致します）。ただし、`kAdvantage` を小さくすると正しい値に近づくまでに多くの試合が必要になり、大きくすると近づいたあとも勝敗のブレで `a` が上下に揺れやすいトレードオフがあります。

### 2. `OnlineNewton`（更新幅の自動調整）

対数尤度 `l(a) = y * ln(p_A) + (1 - y) * ln(1 - p_A)` の1階微分（傾き）と、2階微分にマイナスをつけた量（この試合から得られた情報量）を使って更新します。

```text
初期値: I_0 = onlineNewtonPriorMatches * beta^2 * 0.25   （既定: 20試合分）
更新式: I_t = rho * I_{t-1} + beta^2 * z^2 * p_A * (1 - p_A)
        a_t = a_{t-1} + beta * z * (y - p_A) / I_t
```

ここで `rho = onlineNewtonForgettingFactor ∈ (0, 1]` です。

#### 特徴と設定値の意味

- **最初は大きく、後半は安定**: 最初は `I_t` が小さいため大きく動き、試合が集まって `I_t` が増えるにつれて1試合あたりの更新幅が自動で小さくなります。
- **接戦ほど重く足す**: 互角の試合（`p_A ≈ 0.5`）ほど `p_A * (1 - p_A)` が大きく（最大 `0.25`）なり、実力差が大きくて先後関係なく勝敗が決まる試合（`p_A ≈ 0` や `1`）はあまり足されません。
- **`onlineNewtonPriorMatches`（既定 `20.0`）**: 序盤の暴走や 0 割りを防ぐ、最初のブレーキ役の試合数です。
- **`onlineNewtonForgettingFactor`（既定 `1.0`）**: 全員レート `1500` からスタートして `R_i` と `a` を同時学習する場合、序盤は全員のレートが近いため `a` が小さめに見積もられ、各人のレートが広がるにつれて適正な `a` も大きくなります。`rho = 1.0`（忘れない）だと序盤の重みが残って後半の追従が遅れやすいため、`0.9995` のように少し古い情報を忘れる設定にすると追従しやすくなります。

※本ドキュメントは実装仕様と数式の整理を目的としたものであり、性能の優劣は比較実験で確認します。

## 検証

[advantage_elo_tests.cpp](../tests/advantage_elo_tests.cpp) の CTest（`advantage_elo_unit`）で以下を確認しています。

- `FixedStep` の確率計算・同時更新・交換対称性・通常 Elo との互換性
- `OnlineNewton` の手計算照合（`rho = 1.0` および `rho = 0.9`、許容誤差 `1e-12`）と対称性
- 合成データでの復元・立ち上がり確認（同実力 `1,000` 試合、および `S1` 相当 `100` 人・`100` ラウンド = `5,000` 試合）
- 不正パラメータ・範囲外入力の拒否
