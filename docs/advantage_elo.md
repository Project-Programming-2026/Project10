# Advantage-Elo の設計とオンライン Newton 更新

[実装](../src/ratings/advantage_elo.cpp)（公開ヘッダ: [advantage_elo.hpp](../include/project10/ratings/advantage_elo.hpp)）は、1対1・引き分けなしの対戦において、プレイヤーごとの基礎実力 `R_i` と全プレイヤー共通の条件効果（先手有利）`a` を同時に推定するレーティング手法です。

## 予測モデル

2人の推定レート `R_A`, `R_B`、条件効果 `a`（Eloポイント単位）、先手条件 `z ∈ {+1, -1}`（`+1` は A が先手、`-1` は B が先手）から、A が勝つ確率を次で予測します。

```text
beta = ln(10) / scale
u    = beta * (R_A - R_B + a * z)
p_A  = 1 / (1 + 10^(-(R_A - R_B + a * z) / scale)) = 1 / (1 + exp(-u))
```

## 条件効果 `a` の2つの更新規則

個人レート `R_A`, `R_B` の更新は両モードで共通です（`R_A' = R_A + K * (y - p_A)`、`R_B' = R_B - K * (y - p_A)`、ただし `y ∈ {0, 1}` は A の勝敗）。条件効果 `a` の更新規則は `AdvantageUpdateMethod` で切り替えられます。

### 1. `FixedStep`（v0既定）

```text
a' = a + kAdvantage * z * (y - p_A)
```

固定のステップ幅 `kAdvantage` で更新する設計案（v0）です。`kAdvantage = 0` にすると通常 Elo と一致します。一方、`kAdvantage` が小さいと真の条件効果への立ち上がりに多くの試合数を要し、大きいと収束後に勝敗ノイズで `a` が振動し続けるトレードオフがあります。

### 2. `OnlineNewton`（オンライン Newton 拡張）

1試合の対数尤度 `l(a) = y * ln(p_A) + (1 - y) * ln(1 - p_A)` を `a` で微分すると、1階微分（勾配）と負の2階微分（Fisher情報量）は次のようになります。

```text
dl/da    = beta * z * (y - p_A)
-d²l/da² = beta² * z² * p_A * (1 - p_A)
```

`OnlineNewton` では累積 Fisher 情報量 `I_t` を保持し、忘却係数 `rho = onlineNewtonForgettingFactor ∈ (0, 1]` を用いて試合ごとに次で更新します。

```text
初期値: I_0 = onlineNewtonPriorMatches * beta² * 0.25   （既定: 20試合分）
更新式: I_t = rho * I_{t-1} + beta² * z² * p_A * (1 - p_A)
        a_t = a_{t-1} + beta * z * (y - p_A) / I_t
```

#### 直感的な特徴

- **序盤は大きく・後半は安定**: 実効ステップ幅 `beta / I_t` が、最初は大きく（例: `scale = 400`, `onlineNewtonPriorMatches = 20` の1戦目で約 `33` Eloポイント）、試合数が溜まるにつれて自動で小さくなります。
- **試合の情報量で重み付け**: 互角の試合（`p_A ≈ 0.5`）は `p_A(1 - p_A) = 0.25` と大きく加算され、実力差が極端な試合（`p_A ≈ 0` または `1`）はほとんど加算されません。
- **尺度不変性**: `scale` を変えても `beta / I_t` により単位が自動換算されます。

#### 忘却係数 `rho` が効く理由（同時推定時の注意点）

全プレイヤーが初期レート `1500` から始まる場合、序盤は `R_A - R_B ≈ 0` であるため、潜在能力の個人差によるばらつきが見かけ上ノイズに含まれ、見かけ上の最適な `a` は小さめに出ます。その後、対戦を重ねて各人のレート `R_i` が広がっていくにつれて、条件付きの最適な `a` も徐々に大きくなります。

- `rho = 1.0`（忘却なし）では序盤の `I_t` をすべて記憶し続けるため、後半に `beta / I_t` が小さくなりすぎて、`R_i` の広がりに `a` が追いつくのが遅れる場合があります。
- `rho < 1.0`（例: `rho = 0.9995`、直近約 2,000 試合相当の指数移動Fisher情報量）にすると、古い試合の情報量を緩やかに忘却しながら、序盤の素早い立ち上がりと後半の安定収束を両立できます。また、条件効果が時間変化する設定にも追従しやすくなります。

本ドキュメントはモデルの実装仕様と数式整理を記録するものであり、特定の条件設定に対する最終的な優劣を主張するものではありません。性能差は共通評価パイプライン上の比較実験で確認します。

## 検証

[advantage_elo_tests.cpp](../tests/advantage_elo_tests.cpp) の CTest（`advantage_elo_unit`）で以下を確認しています。

- `FixedStep` の確率計算・同時更新・交換対称性・通常 Elo との互換性
- `OnlineNewton` の2試合手計算照合（`rho = 1.0` および `rho = 0.9`、許容誤差 `1e-12`）
- `OnlineNewton` の A/B・`z`・勝敗反転に対する対称性と `scale` に対する線形スケーリング
- 合成対戦データでの検証（ロジスティックモデル `1,500` 試合での真値復元、および `S1` 相当 `200` 人・`200` ラウンド = `20,000` 試合での有限性・立ち上がり・`rho = 0.9995` による追従確認）
- 不正パラメータ・範囲外入力の拒否
