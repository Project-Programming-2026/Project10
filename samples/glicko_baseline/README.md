# ranked Glicko-2の固定参照分布

[PR #28](https://github.com/Project-Programming-2026/Project10/pull/28)のマージコミット`41345eeb9c500e23dc7655b52a94806a3b34a878`から、`config.json`と`glicko2_rating.csv`を改変せず取り込んでいます。CSVは説明用の架空データではなく、PRに含まれる固定の学習済みレート分布です。

設定に記録された条件はrun ID 3601、1,000人・各200対戦、プロビットモデル、能力分布N(0,1)、performance_std=1、期間・評価間隔10です。能力・組合せ・勝敗のシードはそれぞれ20261016010・20261016020・20261016030です。`comparison`設定はなく、先手有利なしの分布です。

取り込み時のSHA-256は次のとおりです。元の改行形式も保持しています。

```text
6173babea1925a0e1fe9e1b8873a20212aace09507431050f2631545712a1b44  config.json
3b577d2c340a0276ae007f56679ee97120af36372deb97d1399a5f1c2903efd0  glicko2_rating.csv
```

再生成する場合は、設定を`configs/run_3601/config.json`へコピーし、run 3601のデータ生成後に`project10_predict 3601 Glicko2`を実行します。既存の正式結果を上書きしない作業先で行ってください。生成された`runs/run_3601/glicko2_rating.csv`が参照候補になります。同じ設定でも、コード・コンパイラ・標準ライブラリ・数値出力精度などが異なればバイト一致する保証はありません。元の生成時点のコード・環境・入力ハッシュはPRの2ファイルだけでは追跡できず、今回それらまで再生成照合したものではありません。

一括CLIの`--all-methods`は、この分布をrun内の`ranked_reference/glicko_baseline/`へ設定とともに保存します。再利用時はその保存済み分布を使い、別の分布へ暗黙に切り替えません。新規実行前にヘッダー・人数・有限値と、参照run・対応する3シードが評価runと異なることを検査します。分布の学習人数と評価人数は一致を要求しません。独立した追加学習データを利用する比較として扱ってください。
