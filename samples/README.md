# 共有する入力サンプル

`run_0000/` は、既存の `runs/run_0000/` からコピーした1,000人分の生成済みデータです。
CSVは合計約30KBで、設定・チェックサムとともにGit管理対象とします。
各担当者が同じファイルを取得できるため、環境ごとの乱数列の違いを避けて入力を共有できます。
正式な性能比較用データとして採用済みであることは意味しません。
元データの確認できる来歴、再現に使ったコミット・環境・コマンドは[生成来歴と再現確認](PROVENANCE.md)を参照してください。元の生成時に未記録だった情報と、後から確認した再現条件を区別しています。

| ファイル | 内容と利用範囲 |
| --- | --- |
| [run_0000/config.json](run_0000/config.json) | 生成に使用した設定。シードは説明用の値 |
| [run_0000/players.csv](run_0000/players.csv) | プレイヤーID。各レーティング手法へ渡せる共通入力 |
| [run_0000/latent_parameters.csv](run_0000/latent_parameters.csv) | 仮定した潜在能力。生成・評価・検証専用で、レーティング手法へ渡さない |
| [run_0000/SHA256SUMS](run_0000/SHA256SUMS) | 上記3ファイルのSHA-256。変更や取り違えの確認用 |

**対戦履歴はまだありません。** 現在の生成器はプレイヤーIDと潜在能力のみを出力します。
このサンプルでは入力形式や初期化の確認はできますが、実際のレート更新には別途対戦履歴が必要です。
対戦生成を実装したら、共通の対戦履歴も設定・ハッシュと対応づけて共有します。
仮の対戦履歴や未実装CSVを、生成済みの実験データとして追加しないでください。

サンプルは参照用とし、各手法の予測や評価結果は `runs/` に保存します。
内容を変更する場合は、理由と生成条件をレビューできる形で示し、既存の比較との対応を保ちます。
変更後は `SHA256SUMS` も更新してください。共有CSVと設定は `.gitattributes` でGitによる改行変換を抑止しています。

PowerShellでは次のコマンドでハッシュを表示し、`SHA256SUMS` と照合できます。

```powershell
Get-FileHash .\samples\run_0000\config.json, .\samples\run_0000\players.csv, .\samples\run_0000\latent_parameters.csv -Algorithm SHA256
```
